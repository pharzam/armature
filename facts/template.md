# F-NNNN. Short noun phrase naming what this document covers

| Field | Value |
| ------------ | ----- |
| Fact ID | `F-NNNN` |
| Source | Who gave these facts — customer name and role, or the document's title. |
| Collected by | The engineer or agent who captured this record. |
| Date collected | YYYY-MM-DD |
| Origin | Where it came from: meeting, email, call, or file. Link or name the original if one exists. |
| Status | `Raw` — captured as-is, immutable. Set to `Superseded by F-NNNN` if a later record corrects it. |

## Facts as collected

> Paste the customer's words here **unchanged**. Do not paraphrase, shorten, or
> "clean up" the wording — that is the job of the derived layer, not this record.
> Number each fact so a requirement can cite it as `F-NNNN#<n>`. If the source is
> a file, keep the file in the repo and link it in the Origin row above; this
> body then holds the exact quotes the derived requirements depend on.

1. `‹first fact, in the customer's own words›`
2. `‹second fact›`
3. `‹…›`

## Notes on capture (optional)

> Facts about the *capture itself*, kept separate from the facts themselves: who
> was present, what was unclear or left open, what still needs confirmation. This
> is provenance, not interpretation — keep requirement-writing out of it. Delete
> this section if there is nothing to record.
